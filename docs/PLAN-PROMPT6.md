### Auth y cuenta — agente A (`routes/auth.ts`, `routes/cuenta.ts`, `schemas/cuenta.ts`, `lib/referidos.ts`, `lib/google-oauth.ts`)

- `POST /auth/register` acepta además `ref?: string` (código de referido; si existe, `referidoPorId`), manda BIENVENIDA.
- `POST /auth/recuperar {email}` → 204 siempre (si existe: `PasswordReset` con `tokenHash` sha256, vence 60 min, email RECUPERAR_PASSWORD con `{{link}}` = `${WEB_URL}/restablecer/<token>`).
- `POST /auth/restablecer {token, password}` → 204; marca `usadoEn`, revoca refresh tokens del usuario.
- `GET /auth/google?next=/mi-cuenta` → 302 a Google (scope openid email profile, `state` firmado/cookie). `GET /auth/google/callback?code&state` → crea/vincula usuario por `googleId` o email (rol CLIENTE), `issueSession`, 302 a `${WEB_URL}${next}`; error → `${WEB_URL}/ingresar?error=google`. `redirect_uri` = `${WEB_URL}/api/auth/google/callback` (pasa por el proxy same-origin de la web; A revisa que el proxy reenvíe 302 + Set-Cookie: `apps/web/src/app/api/[...path]/route.ts` es de A). Sin `GOOGLE_CLIENT_ID` → 404 `GOOGLE_DESHABILITADO`.
- `GET /cuenta` → `{ user: {id,email,nombre,telefono,rol,createdAt,googleVinculado,newsletter,codigoReferido}, resumen: {pedidos,recetas,direcciones,favoritos}, rivedere: {ultimaCompraRecetado: ISO|null, proximoAviso: ISO|null, meses, descuentoPct} }`.
- `PUT /cuenta/datos {nombre, telefono?, newsletter?}` → `{user}`. `PUT /cuenta/password {actual?, nueva}` → 204 (sin `actual` sólo si la cuenta no tiene password: alta por Google).
- `GET /cuenta/pedidos` → `{items: PedidoPublico[]}` (misma forma que `/checkout/mis-pedidos`, con `serializePedido`). `GET /cuenta/pedidos/:id` → PedidoPublico (403 si es de otro).
- `GET /cuenta/recetas` → `{items: Receta[]}` (`serializeReceta` de `lib/pedidos.ts`), `DELETE /cuenta/recetas/:id` (409 si está en un pedido).
- `GET /cuenta/direcciones` → `{items: Direccion[]}`; `POST /cuenta/direcciones` (201), `PUT /cuenta/direcciones/:id`, `DELETE /cuenta/direcciones/:id`, `POST /cuenta/direcciones/:id/predeterminada`. Campos: `etiqueta, direccion, piso, localidad, provincia, codigoPostal, lat, lng, placeId, telefono, predeterminada` (reusar reglas de `direccionInput`).
- `GET /cuenta/favoritos` → `{items: Producto[]}` (serializeProducto de `lib/serialize.ts`, sólo publicados); `GET /cuenta/favoritos/ids` → `{ids: string[]}`; `PUT /cuenta/favoritos/:productoId` → 204; `DELETE /cuenta/favoritos/:productoId` → 204.
- `GET /cuenta/referidos` → `{codigo, link: ${WEB_URL}/r/<codigo>, descuentoPct, referidos: [{nombre (inicial + apellido abreviado), estado: 'REGISTRADO'|'COMPRO', createdAt}], cupones: [{codigo, descripcion, valor, tipo, vigenciaHasta, usos, usosMax}]}` (genera `codigoReferido` si falta: 8 chars A-Z0-9 sin confusos).
- `lib/referidos.ts` `recompensarReferido(pedido, env)`: si `pedido.userId` tiene `referidoPorId` y `referidoRecompensadoEn` es null → en transacción: dos cupones `PORCENTAJE` `valor = ConfigTienda.referidoDescuentoPct`, `usosMax 1`, `usosMaxPorCliente 1`, vigencia 90 días, códigos `REF-<4>-<4>`, descripción "Referido: …", marcar `referidoRecompensadoEn`, email REFERIDO_RECOMPENSA a ambos (vars `nombre, nombreAmigo, codigo, descuento, vigencia`).
- Tests `test/cuenta.test.ts`: registro con ref + BIENVENIDA en `emails_enviados`, recuperar/restablecer (token inválido/usado/vencido), direcciones CRUD + predeterminada, favoritos, recetas, referidos (recompensa al aprobar pago: usar `aprobarPago`/flujo de transferencia como en `checkout.test.ts`), Google callback con `fetch` stubbeado.
